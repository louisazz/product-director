# 逻辑视角

推理的具体方法。它们服务于判断，不需要在回答中展示术语。

## 先识别问题的类型

同一句话可以属于不同类型，类型决定该追问什么：

- **成立条件**："一个能取代 TikTok 的新平台需要什么"——问的是必要条件的集合、其中哪些已被满足、哪一条是当前最紧的约束，以及它们是否必须同时成立。
- **对象定义**："我们做的笔记、计划、作品对用户到底是什么"——问的是这个东西的本质。一个好的重新理解应当用同一个判断解释许多细节。结构抽象需要深入时交给 `kk-skill`。
- **现象解释**："用户为什么不用、为什么这样用"——问的是最佳解释。列出能解释全部观察的候选解释，找出能区分它们的证据。
- **方案取舍**："A 还是 B"——先检查是否假二分，再把各自的蕴含走到尽头，再找真正的判断标准。
- **策略推演**："如果我们做 X 会怎样"——把 X 当作前提推到结论，检查结论是否成立、是否可欲、是否与其他已知的事冲突。
- **验证设计**："怎么知道这个方向对不对"——问的是什么必须为真、什么证据会改变决定、哪些信号有诊断力、什么时候该重新审视。展开见 `learning-plan.md`。
- **需求还原**："用户要 X"——判断 X 是方案、症状还是需求；追问谁在什么处境遇到什么困难、当前如何应对、付出什么代价。
- **下一步**："接下来该做什么"——问的是哪个行动信息量最大：哪条前提最不确定又承担着最多决定，解决它最便宜的方式是什么。目标、指标或路径还在演化时，正确的下一步常常是一次学习而不是一次发布。
- **就绪判断**："这个结果可以用了吗"——问的是它走到了哪一关：能力存在、行为可靠、在安全边界内、已集成、已发布、有反馈。每一关要的证据不同，存在不等于可用。

类型不是标签。一个"取代 TikTok"的问题同时是成立条件问题和对象定义问题——"取代"意味着做同一件事，还是争夺同一段时间？先拆开，再处理。

## 条件关系

**必要与充分。** "没有它不行"是必要，"有了它就行"是充分。大多数产品条件是必要而不充分：创作成本低是内容平台的必要条件，但满足它的产品很多。检查一个理由时先问它属于哪种。

**必要但不区分。** 一个必要条件如果竞争对手已经满足，它不能成为你成立的理由，只能成为你不失败的门槛。区分"必要且稀缺"和"必要但人人都有"。

**促进不是必要。** 必要是没有它达不成，充分是有它就足以达成，促进只是提高概率——既不必要也不充分。把促进因素排成"必须先做"，是最常见的资源误配。

**合取。** 多个必要条件要同时成立才够。列全它们，再分成两组：第一天就必须成立的，和可以在规模之后成立的。要求太多条件同时成立的产品，第一份价值迟迟不会发生——先检查是否存在一条不依赖其他条件的价值路径。反过来，几个必要条件各自成立，也不证明它们合起来足够。

**最紧的约束。** 合取里的条件不是等权的。通常只有一两条当前真正卡住，其余已被满足或顺带就会满足。判断力表现在把力气放在最紧的那条上。

## 前提与量词

**隐含前提的藏身处。** 动词里：取代、打通、整合、拉动、导入——每个都预设了一个没说出来的状态。名词里：平台、社区、生态——预设了答案的形式。类比里："像 X 一样"——预设了 X 的条件在这里也成立。把前提说出来，问题常常直接改变。

**量词。** "用户想要"：全部、多数、还是会迁移的那一小群？"更好"：对谁、在什么时刻、以什么方式？"总是""再也不"：时间上的全称判断几乎总是错的。没有量词的命题无法检验，也无法反驳。

**定义性命题与经验性命题。** "用户需要效率"可能是定义（我们把想要效率的人叫用户），也可能是经验主张（观察到用户在乎效率）。前者不能被证伪，后者可以。分清哪种，才知道该论证还是该验证。

**口径。** 一个词在这轮讨论里指什么，先钉死，否则后面的比较全会滑走。"新客"是首访、新注册还是未付费？"失败"是系统报错还是用户觉得结果不可用？"留存"的分母和窗口是什么？常见的偷换是前面用注册者，比较时悄悄换成首购者。只解决会改变结论的歧义。

**价值的主语。** 用户价值（完成了任务、更省时、获得此前没有的可能）、业务价值（有质量的增长、可持续收入、风险降低）、项目产出（上线了、引入了、办了）是三件事，不自动相等：生成次数上涨可能来自失败重试，付费人数上涨可能伴随更高补贴。说"值得做"时先说清是哪一项值得。再分清谁获得结果、谁承担成本、谁决定采用——三者常常不是同一个人。

**真约束与假约束。** 真约束是客观上改不了的条件；"我们一直这么做""XX 说不能动"是假约束。把假约束当前提，解空间会被凭空砍掉一半。

## 推理形式

**蕴含链。** 策略是一串"如果…那么…"。走到尽头，看终点是否是你要的；也看中途是否需要某个你并不相信的事为真。做决定的人通常只走了前两步，潜在影响藏在后面几步里。链条常常跨层：一个技术选择蕴含一种模型行为，一种模型行为蕴含一种用户体验——每个箭头都可以单独检查。

**逆否。** 如果 S 蕴含 O，而 O 不成立，则 S 不成立。这是检验策略最经济的方式：找到策略必然导致的一个结果，看它是否已经被否定。

**肯定后件的谬误。** 功能上线后指标上涨，不等于功能导致了上涨。"如果 A 则 B，观察到 B"推不出 A。要看同期还有什么变了，以及没上线的对照。

**最佳解释。** 问题定义是对症状的解释。好的解释同时满足：解释全部观察而不是挑选一部分；比其他候选解释更简单；能预测尚未观察到的事。列出至少两个候选解释，找出能区分它们的证据，而不是只为第一个想到的找支持。

**归纳的边界。** 从几个用户推到全部用户、从一个市场推到另一个市场、从过去推到未来，每一步都在假设"其余条件相同"。说出这个假设，判断它是否成立。

**类比。** "像 X 一样"迁移的是机制，不是表象。要说清 X 的机制靠什么成立，两边的关键差异会不会让它失效。相似的界面不等于相似的动因。

## 主张的层次

关于人的长期判断、当前的产品定义、承载定义的具体形式、衡量它的指标，是四个层次。

- 形式失败不推翻定义，定义失败不推翻对人的判断——除非失败恰好击中了上一层的前提。
- 上一层成立也不构成保留下一层的理由。长期信念对，不等于当前形式该留。
- 指标只在定义之下有意义。抄别人的数字而不抄定义，数字是空的。
- 争论时先确认双方在同一层。多数僵局是一方在说定义、另一方在说形式。
- 目标和指标还在演化时，在定义层判断，不在指标层争论。

**结论的强度。** 层次之外还有强度：问题存在 → 因果成立 → 某机制可能有效 → 值得验证 → 值得优先投入 → 可以规模化，六级递增。证据支撑到第几级，结论只能停在第几级。最常见的错是越级——用"问题确实存在"的证据去要"现在就全量做"。先把自己的结论标到哪一级，比被人问出来强。

## 联系与差距

深入工作的人看不见自己工作之下的前提，也看不见相邻工作的存在。看全局的价值在于做这几种检查：

**缺失的联系。** 两个各自成立的判断合在一起推出什么？A 视角知道 A，B 视角知道 B，A 和 B 一起蕴含的 C 没有人说出来。把已知的事两两相合，找没被画出来的推论。

**未解决的假设。** 一个计划压在哪些没人写下来的前提上？专家在深处看不见它们，因为前提在他们的工作之下。把计划倒过来读：它要成立，什么必须先为真。

**承重分析。** 如果这条主张是假的，哪些决定会倒？承重且没有证据的主张最先处理；不承重的主张再有争议也可以放着。

**局部最优对全局。** 一个局部正确的决定在整体上制造什么代价？优化子目标时，子目标和目标在什么条件下分离。做局部的人看不见这个代价，因为代价落在别处。

**相邻问题。** 两条线各自深入，其实在解同一个问题的两个面。看它们的前提是否相同、结论是否互相蕴含。

差距在成为阻碍之前找出来，比之后处理便宜得多。

## 常见谬误

- **幸存者**：只研究赢家。赢家的共同点可能输家也有。
- **竞品有所以要有**：把对方的方案当成需求的证据。对方可能也错了，或者对方的条件不同。
- **假二分**："列表还是瀑布流"——第三个选项常常是问题问错了。
- **沉没成本**：已经投入的不构成继续的理由。只看从现在起的收益和成本。
- **事后归因**：先后发生不等于因果。
- **内部权威**：提出者的职位不构成主张的证据。
- **基率忽略**："多数新平台失败"是基率；一个新想法需要说明它为什么不在多数里。
- **类型错置**：把状态当类型、把角色当身份、把动作放进目的地分类、把业务规则伪装成属性。这类错误在 `kk-skill` 里有完整处理。
- **战略语言掩盖需求不存在**：打通、整合、拉动、导入、多平台、全面——这些词出现时，先找它背后的独立需求。

## 证据

- **没有证据支持不等于有证据反对**，也不等于可以当真。三种状态分开记。
- **预测不如最近真实发生的选择。** 问"你会不会用"得到的是礼貌，问"上次遇到这个问题你做了什么"得到的是行为。
- **定性回答"为什么"和"是什么"，定量回答"多少"和"是否变了"。** 用错了类型，答案看起来有，其实没有。
- **承诺有梯度。** 愿意看、愿意试、愿意带来自己的材料、愿意再来、愿意付钱，是递进的。低一级的证据不能代替高一级的问题。
- **自己的主张也分级。** 已核实、能重建论证、只理解了大意、猜测，是四种不同的可信度。说清自己在哪一级，不夸大；证据变了就改建议。
- **指标要回答决策问题。** 一个好指标先回答：它支持或反驳哪项判断？观察对象、口径和窗口是什么？可能怎样被误读？读到什么结果会改变行动？总体上涨不等于每个群体变好；线上线下冲突时，先查是不是在比同一件事（样本、版本、时间、质量维度），再谈机制。
