# 学习计划

把一个含糊的方向变成可以推进的东西。它不是路线图，也不是任务清单；它回答的是"我们相信什么、凭什么、什么会让我们改主意"。

## 四个问题

**什么必须为真。** 列出这个方向成立所依赖的前提，标出每一条的状态：已验证、有证据、纯假设。承担着决定却没有证据的前提，最该先处理。

**什么证据会改变决定。** 对每条前提，写清什么观察会推翻它。写不出来的前提要么是定义性的（不可证伪），要么还没想清楚。也写清什么观察只是"说明不了什么"——避免把中性结果当成支持。

**哪些信号有诊断力。** 能区分候选解释的观察才是信号。愿意看、愿意试、愿意带来自己的材料、愿意再来，是递进的承诺；实验要碰到当前最危险的那个假设，而不是最容易验证的那个。

**什么时候重新审视。** 触发条件而不是日期：某个前提被推翻、某个信号连续出现、外部条件变了。定义是持续校准的，触发条件让校准有依据。

## 带进来的东西不压扁

用户的话、研究的发现、模型的表现进入判断时，保留它的证据结构：谁、在什么处境、遇到什么、当前怎么应对、付出什么代价。"用户要 X"压掉了所有能区分解释的信息；"某类用户在某个时刻因为某个原因做不到某事"还保留着。

产品是模型行为时，这条阶梯是：用户情境 → 行为失败 → 可测量的评估 → 训练信号。每一级向上都在抽象，每一级都不能跳。一个功能请求通常是从"行为失败"直接跳到了"训练信号"。

## 找差距

- 哪些前提承担着决定，却没有人在验证它。
- 哪些工作正在汇聚——两条线各自深入，其实在解同一个问题。
- 哪些决定在等一个没人负责的答案。
- 哪些局部优化正在为整体制造代价，而做局部的人看不见。

差距在成为阻碍之前找出来，比之后处理便宜得多。

## 叙述的形状

对外说清一个方向时，四段就够：已经学到了什么、仍然不确定什么、需要什么决策、为什么这件事重要。这四段让读的人知道自己该做什么，也让写的人发现自己其实还不知道什么。

## 形式

短，一页以内。它服务于判断的连续性，不服务于汇报。研究和探索是非线性的，计划的作用是让每一次意外都能被放回结构里，而不是规定意外不许发生。目标、指标或路径还在演化时，正确的下一步常常是一次学习循环而不是一次发布；计划要允许这个答案。
