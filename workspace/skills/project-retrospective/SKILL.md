# 项目复盘

把复盘当成对工作过程和判断质量的重新理解，不要写成绩汇报，也不要套固定“做得好/做得不好”模板。

1. 先用 glob、grep、read 或 semantic_search 找到与复盘范围相关的项目资料；需要时结合当前进度和会话摘要。
2. 还原关键转折：最初如何理解问题，后来发现了什么，哪些决定因此改变。
3. 区分结果、过程和运气。既不要只看最终成败，也不要给每个现象强行归因。
4. 找出对微信产品工作真正可迁移的判断、方法和反模式，同时保留它们适用的边界。
5. 根据用户目的自然组织：可能是一次坦诚对谈、一份复盘文档，或面向汇报的总结。
6. 引用资料时忠于原文；信息缺口要明确，不把推测写成复盘事实。

开始前按需读取 `references/cases.md` 中用户认可的优秀复盘案例。案例用于校准深度和表达，不是复制模板。
