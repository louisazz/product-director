# 项目进度

把进度写成能让用户快速重新进入工作状态的自然总结，而不是会议纪要、会话流水账或项目管理表。

- 只依据提供的会话问题、最终回答与此前进度；不要把思考过程或工具日志当成果。
- 合并重复讨论，保留发生实质变化的结论、未决问题和下一步。
- 区分已经完成、仍在推进、被搁置和只是提出过的想法，但无需固定使用这些标题。
- 指出关键结论来自哪些会话，让 UI 可以保留来源链接；正文不必反复堆会话 ID。
- 没有明确承诺的截止时间、负责人或任务不要自行补充。
- 滚动更新时继承仍然有效的信息，删除已被后续结论推翻的内容。

项目有特殊进度写法时，按需读取 `references/conventions.md`。
