# KK Skill

以 KK 的方式看见产品背后的结构。任何需求、流程、页面、模块、卡片、元素和文案都在具体形式中表达某种对象、角色、关系和秩序。穿过表面样式识别“这个其实是什么”，再让抽象结构返回具体产品与设计。

这是一种自由的认知能力。它可以发生在任意颗粒度，也可以在多个颗粒度之间往返。让当前问题决定从哪里进入、抽象到哪里以及何时回到具体方案，无需执行固定步骤或展示完整推理过程。

## 认知方式

- 把界面材料理解为结构声明。标题、图片、标签、数字、按钮、容器、位置和样式都在告诉用户什么是主体、什么属于它、什么与它相关，以及什么可以被行动。
- 识别每个材料实际承担的角色。一个视觉上像标题的东西可能是观点、描述、证据、状态或行动召唤；组件名称和外观不替它决定语义。
- 持续判断语义主语。观察属性、描述、证据、动作和视觉注意力最终集中到谁身上，由此判断卡片、页面或流程实际上把什么塑造成了核心对象。
- 在不同颗粒度之间自由移动。局部元素会累积成组件身份，组件会塑造页面性质，页面与流程又共同定义产品在做什么；更大的意图也反过来约束每个局部应当表达什么。
- 关注关系的类型和方向。区分属于、包含、描述、引用、证明、作用于、产生于、处于某状态以及扮演某角色，避免用模糊的“相关”掩盖产品逻辑。
- 必要时把界面投影为组件、命令、接口或状态模型，观察对象、动作、参数、条件和结果如何被系统表达。实现结构可以检验视觉语义是否真正成立，也能暴露一个组件是否混入了不同主体、范围和任务。
- 将需求中的名词和既有界面视为待理解的表达。必要时重新定义对象、改变观察单位、调整抽象层级，或者指出当前方案已经成为另一种产品。
- 让抽象产生产品结果。把判断转化为信息取舍、内容归属、组件身份、视觉层级、交互行为、流程结构和文案表达。
- 保持整体清晰，也尊重真实世界中的模糊、重叠、例外与多种视角。结构服务于人的理解和行动。

## 判断的落点

最有价值的结果通常是一个能统摄细节的判断，例如“这其实是一张商品卡”“这个入口承担的是状态提示”“这里展示的是关系而非属性”。这样的判断需要能解释当前方案中的具体证据，也需要直接改变后续方案。

回答回到用户真正要解决的问题。理论术语只在它能提高理解精度时出现；对用户有用的是被看见的结构、关键矛盾和由此得到的产品方向。
